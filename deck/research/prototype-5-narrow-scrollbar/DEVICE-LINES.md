# 设备分线（手机 / 平板 / 桌面）—— 这一条横条各走各的渲染规则

票 [#5](https://github.com/SunsetRNE/dsh-github-resident/issues/5) 的收尾件：把「哪一档设备走哪条规则」写死成一份可照抄的判据，
给落地票 [#6](https://github.com/SunsetRNE/dsh-github-resident/issues/6) 用。判据的真源在原型里（`narrow-scrollbar-PROTOTYPE.html` 的
`DEVICE_LINES` / `capDeviceClass` / `capScaleFor`），本文件是它的文字版。

## 分界

| 线 | 判据（这一档当真的宽） | 典型 |
| --- | --- | --- |
| 手机线 | `width ≤ 679` | 手机竖屏 360–430；小屏横屏 |
| 平板线 | `680 ≤ width ≤ 1023` | 平板竖屏 768–834；手机横屏 |
| 桌面线 | `width ≥ 1024` | 桌面窗口、平板横屏 |

判的是**这一档当真的宽**（真机上就是视口宽），不是设备型号 —— 同一个平板横竖屏会落不同线，这是有意的。

## 三条线各管什么

| 维度 | 手机线 | 平板线 | 桌面线 |
| --- | --- | --- | --- |
| 宽不够时 | 走 `capFold` 阶梯：品牌先让、一段一段收字 | **不收字**：全部显示；放不下就横滑 | 走 `capFold` 阶梯（同手机） |
| 单行高 / 字号 | 22px 行 / 12px 字（定论④：不改） | **26px 行 / 12px 字（维护者 2026-10-12 定：默认 26）** | 22px 行 / 12px 字 |
| 可点目标 | 26px 命中区（视觉 22px 不变） | 44px 命中区（小图标也撑到 44） | 20px |
| 滑到头提示 | 两端渐隐 + 边缘箭头（定论②） | 两端渐隐 + 细滚动条 | 不给提示 |
| 弹层落位 | 一律夹取（不越界） | 一律夹取 | 一律夹取 |
| 钉住区 | 不钉（定论①） | 不钉 | 不钉 |
| 点开规则 | 再点收起 / 点空白收起 / 第一下只收菜单（定论③） | 同手机 | 同手机 |

三条线**共用**：钉住区不钉、点开规则、弹层夹取、`capFold` 的顺序与让位单位（手机/桌面线才真的收字）。

## 当天的实测（Chromium 1208，原型页；三档都跑过）

| 档 | 线 | 宽不够怎么办 | 行高 / 点位 | 横条 / 滚动窗 / 内容 | 可点目标不达标数 |
| --- | --- | --- | --- | --- | --- |
| 393px | 手机线 | 收字（阶梯收到底） | 22px / 26px | 389 / 343 / 568（溢出 225） | 0 / 12 |
| 834px | 平板线 | **全部字显示** | 26px / 44px | 808 / 762 / 762（溢出 0） | 0 / 11 |
| 1280px | 桌面线 | 全部字显示 | 22px / 20px | 1254 / 1208 / 1208（溢出 0） | 0 / 11 |

## 落地要注意的两点

1. **命中区不是视觉**：手机 26px、平板 44px 是靠透明 `::after` / padding 撑出来的，段本身尺寸一个数字都不改 ——
   真实现里别用 `min-height` 改行高，否则手机线又回到「22px 视觉」的矛盾上。
2. **平板线不收字**：`capFold` 在平板线上不该动（否则平板一窄就把字收了，和手机线没差别）。
   判据是「这一档放得下全部字就全显示；放不下就横滑 + 提示」，不做中间档。
